# Подключение стандартов к проекту

Цель — сделать проект самодостаточным: коллега клонирует репозиторий, доверяет
папку, и получает те же правила, замки и процедуры, что и все остальные.

## Что и куда кладётся

Разложение по моменту загрузки, а не по темам — это принцип, который держит
контекст маленьким:

| Что | Куда | Когда попадает в контекст |
|---|---|---|
| Стек, команды, слои проекта | `CLAUDE.md` | всегда, каждая сессия |
| Правила стека (Laravel, Vue…) | `.claude/rules/std-*` (симлинк) | когда открыт подходящий файл |
| Правила только этого репозитория | `.claude/rules/*.md` (файл) | по `paths:` или всегда |
| Процедуры | скиллы модулей | когда задача совпала с описанием |
| Запреты и проверки | хуки, линтеры | не грузятся вовсе — исполняются |

## Шаги

### 1. Определи стек фактами, а не догадками

Прочитай `composer.json`, `package.json`, `pyproject.toml`, compose-файлы.
Зафиксируй версии — они пойдут в CLAUDE.md. Не пиши «Laravel», пиши «Laravel 11».

### 2. Слинкуй правила стека

```
"${CLAUDE_PLUGIN_ROOT}/scripts/std-link.sh" --auto
```

Если автодетект промахнулся — перечисли модули руками. Скрипт сам добавит
симлинки в `.gitignore`: у них абсолютные пути, в git им нельзя.

### 3. Создай `.claude/settings.json`

Чтобы коллеге не пришлось ничего ставить руками:

```json
{
  "extraKnownMarketplaces": {
    "vibe-rules": {
      "source": { "source": "github", "repo": "DanielLetto2020/vibe-rules" }
    }
  },
  "enabledPlugins": {
    "std-core@vibe-rules": true,
    "std-php-laravel@vibe-rules": true
  }
}
```

Этот файл коммитится. При доверии папки Claude Code предложит поставить
маркетплейс автоматически.

### 4. Напиши CLAUDE.md — только то, что уникально для этого репозитория

Держись 200 строк на весь постоянный контекст. Общие правила фреймворка туда
не переписывай: они приедут модулем и загрузятся по путям файлов.

Что должно быть:
- стек и версии;
- команды: тесты, линтеры, сборка, запуск (точные, копируемые);
- карта слоёв — где что лежит и что куда нельзя импортировать;
- 3–7 «здесь всегда так» — то, чего нельзя вывести из кода;
- ловушки этого проекта (легаси-модуль, который нельзя трогать, и почему).

Чего быть не должно: пересказ структуры директорий (модель прочитает сама),
общеизвестные практики фреймворка, вежливые пожелания вроде «пиши чистый код».

### 5. Проверь, что всё доехало

Скажи пользователю выполнить `/context` в новой сессии и убедиться, что нужные
файлы в списке Memory files. Затем `/std-core:doctor` — он покажет журнал
фактических загрузок и найдёт правила с мёртвыми `paths:`.

Пока это не проверено — считай, что стандарты не подключены.
