Обнови стандарты до свежей версии:

```
"${CLAUDE_PLUGIN_ROOT}/scripts/std-update.sh" $ARGUMENTS
```

Скрипт делает три шага подряд: обновляет каталог маркетплейса, обновляет все
установленные плагины стандартов, проверяет симлинки правил в проекте
и перепривязывает их, если путь установки изменился.

Шаги идут вместе не для красоты. Каждый по отдельности выглядит выполненным,
а результата не даёт: обновлённый каталог не меняет установленные плагины,
обновлённые плагины оставляют симлинки на старый путь, и правила молча
перестают загружаться.

`--check` и `--dry-run` показывают текущие версии, ничего не меняя.

После выполнения:

1. **Скажи про перезапуск сессии.** Обновление плагинов применяется только
   после него — без этого человек увидит старое поведение и решит, что
   обновление не работает.

2. **Предложи `/std-core:setup`**, если в стеке проекта могли появиться новые
   модули. Он доустановит недостающее, не трогая профиль.

3. **Если плагины не установлены** — скажи, что настройка проекта делается
   одной командой `/std-core:setup --scope project`, а не установкой
   по одному.

Проверить, что действует после обновления: `/std-core:doctor`.
