# Базовые договорённости

Это единственный файл стандартов, который грузится в каждую сессию.
Всё остальное приезжает по путям файлов или по задаче.

- Тест меняем, только когда изменилось требование. Тест, падающий из-за бага,
  чинится в коде — не в тесте и не в моке.
- Новая зависимость обсуждается отдельно: пакет проходит любые тесты идеально,
  и этот риск автопроверками не закрывается.
- Секреты — только в переменных окружения, в `.env.example` идёт плейсхолдер.
- Правки в миграциях, API-контрактах, конфигах CI, авторизации и всём,
  что касается денег, требуют явного человеческого ревью независимо от того,
  зелёные тесты или нет.
- Новый файл пишется по образцу соседних того же вида, а не по общему идеалу:
  единообразие внутри проекта важнее внешнего образца. Расходится принятое
  здесь с правилом — скажи человеку и спроси, что важнее.
- Если требование противоречит правилу проекта — скажи об этом, не выбирай молча.

## Файл, которого коснулись

Правила действуют не только на новые строки. Тронул файл — сверь его целиком
с правилами, которые на него распространяются; после записи хук назовёт их
поимённо.

- Несоответствия **в границах своей правки** приводи в порядок сразу, без
  отдельной просьбы. Так проект, написанный вразнобой, выравнивается по мере
  работы, а не в отдельном «рефакторинге когда-нибудь».
- Расхождения **шире правки** называй человеку и спрашивай, чинить ли сейчас.
  Молча переписывать чужой код нельзя: диффы на сотни строк не читаются,
  а в проекте без тестов такая правка ничем не подстрахована.
- Не оформляй приведение к стандарту отдельным коммитом поверх непроверенного
  кода: сначала то, ради чего файл открывали.
