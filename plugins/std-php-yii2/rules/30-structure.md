# Yii 2: компоненты, конфигурация, миграции

Yii построен на глобальном контейнере: `Yii::$app` доступен отовсюду. Это
удобно ровно до момента, когда нужно вызвать код из консоли, из теста или
из второго приложения — и выясняется, что он завязан на веб-запрос.

- `Yii::$app` не используется внутри доменной логики. Зависимости приходят
  в конструктор компонента: иначе класс невозможно проверить без поднятого
  приложения.
- Компонент объявляется в конфигурации, а не создаётся через `new` по месту.
  Тогда его подмена — правка одной строки конфига, а не поиск по проекту.
- Конфигурация разделена на общую, веб- и консольную. Дублирование настроек
  между ними расходится при первой правке.
- Секреты и адреса берутся из окружения, а не из файлов конфигурации в git.
  Локальные отличия — в файле, который не коммитится.
- В консольных командах не предполагается наличие пользователя, сессии
  и запроса: то же действие должно работать из cron.
- Миграция обратима: `safeDown()` возвращает схему к прежнему виду или
  явно объявляет, что откат невозможен. Молчаливое `return false` через
  полгода читается как недосмотр.
- Изменение колонок разносится по релизам: сначала добавили новую и
  наполнили, потом переключили код, потом убрали старую. Одновременная
  выкладка кода и несовместимой схемы гарантирует простой.
- Миграция не содержит бизнес-логики поверх данных без ограничения на объём:
  `UPDATE` по миллионам строк в одной транзакции блокирует таблицу.
- Поведения (`behaviors`) применяются для сквозных вещей — отметок времени,
  журналирования, доступа. Бизнес-правило, спрятанное в поведение, не видно
  в месте, где оно срабатывает.
- Кэш инвалидируется по зависимостям или тегам, а не по времени наугад.
  Кэш «на час» означает час неверных данных после каждого изменения.
