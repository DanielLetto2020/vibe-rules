# Yii 2: производительность и тесты

## ActiveRecord и нагрузка

- ActiveRecord удобен, пока объектов немного. Выборка на десятки тысяч записей
  создаёт столько же объектов, и память кончается раньше, чем время запроса.
  Для больших выборок — массивы (`asArray()`) или запрос без ORM.
- Заполнение моделей из внешних данных «пачкой» открывает запись в любое
  поле, включая те, которых не было в форме. Список разрешённых полей задаётся
  явно.
- Связи грузятся через `with()`. Обращение к связи в цикле — запрос на каждой
  итерации; на сотне записей это сотня запросов.
- Для сложной предметной области ActiveRecord перестаёт помогать: он привязывает
  сущности к структуре таблиц. Тогда переходят на ORM, отделённую от схемы,
  а ActiveRecord остаётся для служебного функционала — см. модуль
  `std-arch-approach`.

## Пропускная способность

Приёмы применяются в этом порядке, а не одновременно: каждый следующий дороже
в эксплуатации.

1. Кэширование того, что не меняется от запроса к запросу.
2. Материализованные представления для тяжёлых расчётов.
3. Горизонтальное масштабирование: больше экземпляров приложения, реплики
   для чтения.
4. Разделение крупного сервиса на несколько — когда границы уже видны
   по нагрузке и по владению, а не «на будущее».
5. Секционирование и шардирование данных — последний шаг, он необратим
   без переноса данных.

## Тесты

- Модульные тесты покрывают внутренние модули сервиса, приёмочные — API
  и сценарии целиком. Одних приёмочных мало: они долгие и не указывают
  на место поломки.
- Тест не зависит от состояния базы, оставленного другим тестом. Фикстуры
  готовятся и убираются самим тестом.
- Внешние сервисы в тестах подменяются. Тест, обращающийся к чужому API,
  красный не потому, что код сломан.
