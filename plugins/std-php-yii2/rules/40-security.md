# Yii 2: доступ и вывод

Yii даёт готовые механизмы почти для всего, о чём говорят в разделе
безопасности. Уязвимости появляются не от их отсутствия, а от обхода:
ручная проверка вместо фильтра доступа, вывод без экранирования, доверие
к данным формы.

- Доступ проверяется фильтром в поведениях, а не условиями внутри действия.
  Условие в действии легко забыть в новом действии — фильтр применяется ко
  всем.
- Проверка «свой ли это объект» выполняется при выборке, а не после неё:
  запрос ограничивается владельцем, иначе чужая запись сначала загружается.
- Вывод в шаблоне экранируется. Вывод без экранирования допустим только для
  заведомо безопасного HTML, прошедшего очистку.
- Массовое присваивание работает только по объявленным правилам проверки:
  атрибут без правила не заполняется, и это защита, а не неудобство.
- Защита форм от подделки запроса включена; отключение для отдельного
  действия сопровождается причиной и проверкой источника другим способом.
- Правила проверки загружаемых файлов задаются валидатором файла с явными
  расширениями и предельным размером, а не проверкой присланного типа.
- Сообщения об ошибках в рабочей среде не показывают стек и запросы.
  Режим отладки выключен, и это проверяется при выкладке, а не на слово.
- Ключ проверки подлинности и параметры соли не лежат в репозитории:
  их утечка равносильна выдаче сессий.
- Прямые запросы собираются с параметрами. Условие, собранное строкой
  из данных формы, — инъекция даже внутри построителя запросов.
- Права выдаются ролями, а не сравнением идентификаторов и имён:
  проверка `id === 1` переживает любую смену администратора.
- Действия, меняющие данные, доступны только методом записи, а не переходом
  по ссылке: ссылка на удаление уходит в предпросмотр и в поисковый робот.
