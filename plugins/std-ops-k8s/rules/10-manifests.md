# Kubernetes: манифесты

Тесты приложения не видят ничего из этого файла. Ошибка здесь роняет сервис
целиком, при полностью зелёном коде.

- `requests` и `limits` заданы. Под без requests планировщик разместит куда
  угодно; под без limits по памяти утащит за собой соседей по узлу.
- Probe'ы различаются по смыслу: `liveness` — процесс жив, `readiness` —
  готов принимать трафик. Одинаковые probe'ы приводят к перезапуску живого
  процесса, который просто ждёт базу.
- `readiness` обязателен, иначе трафик пойдёт в под до готовности,
  и обновление даст всплеск ошибок.
- Образ — по тегу версии или дайджесту. `latest` вместе с
  `imagePullPolicy: Always` означает, что перезапуск пода может подтянуть
  другую версию, и разные поды окажутся разными.
- Секреты — из `Secret` или внешнего хранилища, никогда не значением
  в манифесте: манифесты лежат в git.
- Стратегия обновления задана явно, `maxUnavailable` и `maxSurge` подобраны
  так, чтобы обновление не уронило пропускную способность.
- Для сервисов с более чем одной репликой задан `PodDisruptionBudget`, иначе
  плановое обслуживание узлов может остановить все реплики разом.
- Ограничения безопасности: `runAsNonRoot`, `readOnlyRootFilesystem`,
  `allowPrivilegeEscalation: false`.
- Реплик больше одной и заданы правила распределения по узлам — иначе отказ
  одного узла означает отказ сервиса.
- Каждое изменение манифеста читает человек. Всегда.
