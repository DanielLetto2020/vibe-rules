# PHP: безопасность

PHP чаще всего стоит на границе с интернетом, и почти все классические
уязвимости веба воспроизводятся на нём в одну строку. Это тот случай, когда
правило дешевле инцидента на несколько порядков.

- Запрос к базе — только с параметрами. Конкатенация значения в SQL —
  инъекция, независимо от того, откуда значение пришло.
- Экранирование при выводе делается по месту вывода и по контексту: HTML,
  атрибут, JavaScript и URL экранируются по-разному.
- Пароли хранятся через `password_hash` с алгоритмом по умолчанию. Свои
  схемы с `md5`, `sha1` и солью — гарантированная утечка.
- Секреты не лежат в коде и в репозитории. Ключ, однажды попавший в git,
  считается скомпрометированным навсегда — его меняют, а не удаляют коммит.
- Сравнение секретов, токенов и подписей — `hash_equals`, а не `===`:
  обычное сравнение выдаёт длину совпадения по времени ответа.
- Данные из запроса не попадают в `include`, `require`, `unserialize`,
  `eval`, `system` и функции работы с файлами без белого списка.
- Загруженные файлы проверяются по содержимому, а не по расширению и не по
  присланному `Content-Type`, и сохраняются вне каталога, отдаваемого
  веб-сервером.
- Случайные значения для токенов и идентификаторов — `random_bytes`.
  `rand`, `mt_rand` и `uniqid` предсказуемы.
- Ответ на вопрос «существует ли такой пользователь» одинаков при неверном
  логине и неверном пароле: разные ответы позволяют перебирать учётки.
- Сообщения об ошибках наружу не содержат путей, запросов и стека.
  Подробности — в журнал, пользователю — идентификатор ошибки.
- Внешние запросы идут по фиксированным адресам или проверенному списку:
  URL из пользовательского ввода превращает сервер в прокси во внутреннюю
  сеть.
- Загрузка и обработка данных ограничены по размеру и времени: без лимита
  один запрос кладёт процесс.
