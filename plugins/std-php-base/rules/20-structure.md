# PHP: устройство кода

Язык позволяет обратиться откуда угодно куда угодно: статический вызов,
глобальная функция, синглтон. Всё это работает, пока не понадобится
подменить зависимость в тесте или вынести кусок в другой сервис.

- Зависимости приходят через конструктор. Класс, создающий свои зависимости
  сам (`new PdoConnection(...)` внутри метода), не подменяется в тесте
  и не переносится в другое окружение.
- Статический вызов — только для чистых функций без состояния. Статика,
  хранящая данные, — глобальная переменная с другим синтаксисом.
- Синглтон не заводится вручную: время жизни объекта — задача контейнера,
  а не самого класса.
- Класс имеет одну причину для изменения. Признак нарушения — «и» в описании
  того, что он делает.
- Публичный метод — часть контракта. Всё, что не предназначено для вызова
  снаружи, объявлено `private` или `protected` сразу, а не потом.
- Наследование — только для настоящей замены типа. Переиспользование кода
  делается композицией: наследник, который не подходит вместо родителя,
  ломается в первом же полиморфном вызове.
- Интерфейс вводится, когда есть вторая реализация или нужна подмена в тесте.
  Интерфейс на один класс — лишний файл и лишний переход при чтении.
- Значения предметной области заворачиваются в объекты-значения: телефон,
  почта, деньги, идентификатор. Тогда проверка живёт в одном месте,
  а не на каждой границе.
- Магические методы (`__get`, `__call`) не используются в прикладном коде:
  они отключают автодополнение и статический анализ.
- Глобальное состояние (`$GLOBALS`, `static` в функциях, суперглобальные
  массивы в бизнес-логике) запрещено — оно превращает порядок вызовов
  в неявную зависимость.
- Один класс на файл, имя файла совпадает с именем класса, автозагрузка
  по PSR-4.
- Ориентир по размеру: метод до 30 строк, класс до 300. Превышение — не
  ошибка сама по себе, но повод проверить, не смешаны ли две ответственности.
