# PHP: язык

Правила уровня языка. Действуют в любом PHP-проекте независимо от фреймворка —
Laravel, Yii, Symfony или его отсутствия.

- `declare(strict_types=1)` в каждом файле. Без него PHP молча приведёт
  строку `"12abc"` к числу `12`, и ошибка проявится где-то дальше.
- Типы у всех параметров, возвращаемых значений и свойств. Отсутствие типа —
  это `mixed`, то есть отказ от проверки.
- Сравнение только строгое (`===`, `!==`). `0 == "текст"` и `"1e2" == "100"`
  ведут себя не так, как ожидает большинство.
- Ошибка сообщается исключением, а не возвратом `null`/`false`. Возврат
  `false` при ошибке заставляет вызывающий код гадать, что произошло.
- Ловим конкретные типы исключений. `catch (\Throwable)` без повторного
  выброса прячет ошибки, которые нужно чинить.
- Подавление ошибок оператором `@` запрещено.
- Неизменяемые по смыслу данные — `readonly`. Класс, не рассчитанный
  на наследование, — `final`.
- Массив как структура данных с фиксированными ключами — плохая идея:
  ключи невозможно проверить типами. Используй объект или именованный тип.
- Значения из внешнего мира (запрос, файл, ответ API, БД) приводятся к типу
  явно и в одном месте — на границе, а не в каждой точке использования.
- Строки в двойных кавычках — только при интерполяции.
- Стиль кода — PSR-1 и PSR-12, проверяется автоматически. Обсуждать
  форматирование на ревью — трата времени всех участников.
- Версии выпускаемых пакетов — по семантическому версионированию, тегом в git.
  Ломающее изменение без смены старшей версии ломает всех, кто зависит.
