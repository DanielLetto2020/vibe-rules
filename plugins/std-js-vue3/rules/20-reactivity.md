# Vue 3: реактивность

Реактивность Vue выглядит как обычные переменные, и это её главная ловушка:
присваивание, разрушающая деструктуризация и обычный объект ведут себя
по-разному, а ошибка проявляется как «данные не обновляются» без всякой
диагностики.

- Производное значение — `computed`, а не `watch`, записывающий в `ref`.
  Watch для вычисления даёт лишний рендер и рассинхронизацию при каждом
  новом источнике данных.
- `watch` — для побочных эффектов: запрос, запись в хранилище, переход.
  Если в теле только присваивание — нужен `computed`.
- Реактивность теряется при деструктуризации `reactive`-объекта и при
  передаче `.value` в функцию. Передавай сам `ref` или используй `toRefs`.
- Пропсы не деструктурируются с потерей реактивности: `const { id } = props`
  замораживает значение на момент вызова.
- `watch` на объекте без `deep` не сработает на изменение вложенного поля,
  а с `deep` сработает на каждое — выбор делается осознанно, а не по
  привычке ставить `deep: true` везде.
- Побочный эффект, созданный в `setup`, снимается в `onUnmounted`:
  таймеры, слушатели, подписки, `IntersectionObserver`.
- Асинхронный код после `await` в `setup` теряет контекст компонента —
  регистрировать хуки жизненного цикла там уже нельзя.
- Тяжёлое вычисление в шаблоне выносится в `computed`: выражение в шаблоне
  пересчитывается на каждый рендер.
- `v-if` и `v-for` не соседствуют на одном элементе: приоритет неочевиден
  и меняется между версиями. Оборачивай в `template`.
- Composable возвращает `ref`/`computed` и функции, а не голые значения —
  иначе вызвавший получит снимок вместо живых данных.
- Composable, создающий состояние на модульном уровне, делает его общим
  для всех компонентов. Это либо намеренный синглтон, либо утечка данных
  между экземплярами — третьего нет.
