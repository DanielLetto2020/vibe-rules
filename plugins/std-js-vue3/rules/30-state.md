# Vue 3: состояние и связи между компонентами

Состояние, положенное не туда, — самая дорогая ошибка во фронтенде: она
не ломает ничего сразу, но через полгода любое изменение задевает половину
приложения.

- Состояние живёт на минимальной высоте: внутри компонента, пока им не
  пользуется второй. Глобальный store «на всякий случай» превращает локальную
  правку в правку общего контракта.
- Направление обмена одно: данные вниз пропсами, события вверх. Компонент,
  меняющий состояние родителя напрямую, делает порядок обновлений
  непредсказуемым.
- `provide`/`inject` — для сквозных вещей (тема, локаль, конфигурация),
  а не способ не передавать пропсы. Неявная связь не видна в месте
  использования и ломается при переносе компонента.
- Store хранит состояние, а не разметку и не результаты вычислений, которые
  выводятся из уже имеющихся полей — для них `computed`.
- Данные с сервера не дублируются в store, если они уже кэшируются слоем
  загрузки. Две копии расходятся, и выигрывает та, что обновилась последней.
- Изменение состояния — через действия store, а не присваиванием полей
  снаружи: иначе список мест, где состояние меняется, неограничен.
- Состояние формы не переносится в глобальный store, пока форма не должна
  переживать переход между страницами.
- `v-model` на компоненте реализуется через `defineModel` или пару
  `modelValue`/`update:modelValue` — самодельные варианты ломают ожидания.
- Модалки, тосты и загрузка — общий слой с явным состоянием, а не булев флаг
  в каждом компоненте: иначе два открытых окна перекрывают друг друга.
- Состояние, восстанавливаемое из URL (фильтры, страница, вкладка), хранится
  в URL. Иначе перезагрузка и ссылка коллеге дают разные экраны.
