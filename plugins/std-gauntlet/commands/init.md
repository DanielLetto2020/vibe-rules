Настрой конвейер проверок для этого проекта.

## 1. Выясни, чем проект проверяется сейчас

Прочитай `composer.json`, `package.json`, `pyproject.toml`, `Makefile`,
конфигурацию CI. Выпиши реальные команды: стиль, типы, тесты. Не выдумывай —
если команды нет, так и скажи.

## 2. Проверь, чего не хватает

Отдельно отметь, установлено ли мутационное тестирование (Infection для PHP,
Stryker для JS/TS, mutmut для Python). Обычно его нет — это нормально
и это главный пробел, который стоит закрыть.

Готовые конфиги: `configs/` в модулях `std-gauntlet` и модулях стека.

## 3. Создай `.claude/gauntlet.json`

```json
{
  "gates": {
    "style": "./vendor/bin/pint --test",
    "types": "./vendor/bin/phpstan analyse --no-progress",
    "test": "php artisan test",
    "mutation": "./vendor/bin/infection --threads=max --min-msi=$MSI --no-progress"
  },
  "mutation": { "minMsi": 70 },
  "requireBeforeCommit": true
}
```

Порядок ключей — это порядок запуска: дешёвое и быстрое первым, чтобы
очевидная ошибка находилась за секунды, а не после мутационного прогона.

## 4. Определи стартовый порог честно

Не ставь 80% с потолка. Прогони мутационное тестирование один раз, посмотри
фактическую цифру и поставь порог **чуть выше текущего значения**. Порог,
который не достигается, отключают в первый же день; порог на пару пунктов
выше текущего заставляет каждую задачу немного улучшать тесты.

Запиши текущее значение в `CLAUDE.md` проекта, чтобы было видно динамику.

## 5. Проверь

```
/std-gauntlet:run --list     что будет запущено
/std-gauntlet:run --fast     всё, кроме мутационного
```

Скажи пользователю фактическую цифру mutation score. Если она низкая при
высоком покрытии — это и есть главный аргумент за весь конвейер, покажи её.
