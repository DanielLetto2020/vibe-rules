# JS/TS: работа с данными

Ошибки этого слоя не падают — они дают неверный результат. Отсортированный
не так список, потерянное при копировании поле, сравнение объектов, которое
всегда ложно: код работает, а данные неправильные.

- Копирование объекта через расширение — поверхностное: вложенные объекты
  остаются общими, и правка копии меняет оригинал. Для глубокой копии —
  `structuredClone`.
- Сортировка чисел требует функции сравнения: по умолчанию элементы
  сравниваются как строки, и `[10, 9]` остаётся в этом порядке.
- `sort` и `reverse` меняют исходный массив. Если он чужой — копируй
  перед сортировкой или используй неизменяющие варианты.
- Сравнение объектов и массивов оператором равенства сравнивает ссылки,
  а не содержимое: два одинаковых объекта не равны никогда.
- Порядок ключей объекта не произволен: целочисленные ключи идут первыми
  и по возрастанию. Полагаться на порядок вставки нельзя.
- Для набора уникальных значений — `Set`, для соответствий — `Map`. Объект
  в роли словаря наследует ключи прототипа и приводит ключи к строкам.
- Числа сравниваются с допуском, если это результат вычислений: проверка
  точного равенства для дробных даёт ложь на арифметике.
- Большие целые числа за пределами безопасного диапазона (идентификаторы
  из базы, суммы в минимальных единицах) передаются строкой или `BigInt`:
  разбор такого числа молча его округляет.
- Разбор чисел из строк — явный, с проверкой результата. `parseInt("08abc")`
  вернёт `8`, а не ошибку.
- Локальнозависимые операции (сравнение строк, форматирование чисел и дат)
  выполняются с явно указанной локалью, иначе результат зависит от машины.
- Перебор больших массивов цепочкой преобразований создаёт промежуточный
  массив на каждом шаге. Там, где это заметно, — один проход.
