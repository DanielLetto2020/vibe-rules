# JS/TS: ошибки и отмена

Ошибка, пойманная и проглоченная, хуже упавшего процесса: приложение
продолжает работать в состоянии, которого не предполагал никто, и настоящая
причина теряется за десять шагов до симптома.

- `catch` без обработки запрещён. Либо действие, либо сообщение
  пользователю, либо проброс выше — но не пустой блок и не голый
  `console.error`.
- Ошибка не превращается в `null`. Возврат «пустого результата» вместо
  отказа переносит падение на следующий слой, где причину уже не видно.
- При пробросе сохраняется первопричина (`cause`). Новая ошибка без ссылки
  на исходную стирает стек, по которому только и можно найти место отказа.
- Ошибки предметной области — отдельные типы, а не строки в сообщении.
  Разбирать текст ошибки регулярным выражением — гарантированная поломка
  при первой правке текста.
- Ошибка пользователя (неверный ввод) и ошибка системы (база недоступна)
  обрабатываются по-разному: первую показываем, вторую логируем.
- В сообщение об ошибке не попадают токены, пароли и персональные данные:
  логи читает больше людей, чем кажется.
- Отменяемые операции получают `AbortSignal`. Запрос, результат которого
  уже не нужен, должен прекращаться, иначе гонка приведёт к тому, что
  ответ на старый запрос перезапишет свежие данные.
- Повторы (retry) — только для заведомо идемпотентных операций и
  с задержкой. Повтор платежа по таймауту создаёт второй платёж.
- Таймаут задан явно для любого сетевого вызова. По умолчанию `fetch`
  ждёт бесконечно, и зависший запрос выглядит как зависшее приложение.
- Глобальный перехватчик (`unhandledrejection`, `uncaughtException`) есть,
  но он для журнала и корректного завершения, а не способ не писать
  обработку на месте.
