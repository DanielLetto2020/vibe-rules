# FastAPI

- Вход и выход описываются моделями Pydantic. `dict` в сигнатуре обработчика
  означает отсутствие валидации и отсутствие контракта в схеме.
- Модель ответа задаётся явно (`response_model`). Возврат ORM-объекта напрямую
  утечёт в API любое новое поле таблицы, включая хеш пароля.
- Обработчик не содержит бизнес-логики: разобрал запрос, вызвал сервис, вернул
  ответ. Логика тестируется без HTTP-слоя.
- Общие ресурсы (сессия БД, клиент, текущий пользователь) — через `Depends`,
  а не глобальными переменными: иначе их невозможно подменить в тестах.
- В `async def` не должно быть блокирующих вызовов — `requests`, `time.sleep`,
  синхронный драйвер БД. Один такой вызов блокирует весь event loop, а не
  только свой запрос. Если библиотека синхронная — используй `def`, FastAPI
  сам вынесет обработчик в пул потоков.
- Ошибки — `HTTPException` с осмысленным кодом. 500 в ответ на невалидный
  ввод — это скрытая 4xx.
- Внутренние подробности наружу не отдаём: текст исключения, стек, SQL-запрос
  в теле ответа — подсказка атакующему.
- Фоновые задачи длиннее секунды — в очередь, не в `BackgroundTasks`:
  при перезапуске процесса они просто исчезнут.
- Здоровье процесса и готовность принимать трафик — разные эндпоинты
  (`/healthz` и `/readyz`), иначе оркестратор перезапустит живой процесс,
  который просто ждёт базу.
