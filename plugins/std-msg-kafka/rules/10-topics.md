# Kafka

Kafka — не очередь задач, а упорядоченный журнал. Большинство ошибок здесь
из-за попытки использовать её как RabbitMQ.

- **Порядок гарантируется только внутри партиции.** Сообщения, для которых
  порядок важен (события одного заказа, одного пользователя), обязаны иметь
  один ключ — иначе они разъедутся по партициям и обработаются вразнобой.
- Ключ выбирается по бизнес-сущности. Случайный ключ равномерно нагружает
  партиции и полностью убивает порядок.
- Оффсет фиксируется **после** обработки. Автокоммит по таймеру подтвердит
  сообщения, которые ещё не обработаны, и при падении они будут потеряны.
- Обработка идемпотентна: доставка «хотя бы один раз» — режим по умолчанию.
- Схема сообщений версионируется, изменения обратно совместимы: добавление
  необязательного поля — можно, удаление и смена типа — нет. У журнала есть
  старые записи, и их будут читать.
- Число партиций закладывается с запасом: увеличить его можно, но это ломает
  привязку ключа к партиции, то есть порядок.
- Ошибка обработки не должна останавливать всю партицию навсегда: битое
  сообщение уходит в отдельный топик, а не перечитывается бесконечно.
- Потребители в одной группе делят партиции. Потребителей больше, чем
  партиций, — лишние простаивают, это не масштабирование.
- Лаг потребителя мониторится. Растущий лаг — единственный ранний признак
  того, что система не справляется.
