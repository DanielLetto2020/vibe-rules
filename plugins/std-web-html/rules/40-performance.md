# HTML: скорость загрузки страницы

Скорость страницы определяется не размером кода, а порядком, в котором браузер
получает и обрабатывает ресурсы. Одна строка в разметке способна отложить
первую отрисовку на секунды — и это не видно в разработке на локальной машине.

- Всё, что нужно для первого экрана, загружается первым и с явным приоритетом.
  Остальное — отложенно.
- Изображения ниже первого экрана — с ленивой загрузкой; главное изображение
  первого экрана — наоборот, с высоким приоритетом и без ленивости.
- Размеры изображений заданы, форматы современные, для разных экранов —
  разные файлы через `srcset`. Картинка на 4000 пикселей в блоке шириной 300 —
  самая частая причина медленной страницы.
- Шрифт подключается заранее и с запасным вариантом. Невидимый текст в ожидании
  шрифта — это пустой экран, который пользователь считает поломкой.
- Сторонние виджеты (карты, видео, чаты) подключаются по действию
  пользователя или при попадании в область просмотра, а не сразу.
- Встроенные видео и карты — через заглушку с изображением. Плеер тянет
  сотни килобайт скриптов ради кадра, который могут не посмотреть.
- Разметка не меняет геометрию после загрузки: у баннеров, объявлений
  и подгружаемых блоков заранее зарезервировано место.
- Число запросов к разным доменам ограничено: каждый новый домен —
  это отдельное соединение со своим временем установки.
- Критичные стили доставляются вместе со страницей, остальные — отдельно.
  Один большой файл стилей блокирует отрисовку целиком.
- Страница остаётся пригодной без JavaScript в той части, где это возможно:
  ссылки ведут по адресам, формы отправляются, текст виден.
- Измеряется не «ощущается быстро», а числа на медленном соединении
  и слабом устройстве: локальная машина разработчика — не показатель.
