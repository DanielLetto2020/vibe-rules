# HTML: разметка и доступность

Разметка — единственный слой, который видит не только браузер: ещё поисковик,
скринридер и режим чтения. Ошибки здесь не ловятся ни типами, ни тестами
на бизнес-логику.

- Элемент выбирается по смыслу, а не по виду: `button` для действия, `a`
  для перехода. `div` с обработчиком клика не получает фокус с клавиатуры
  и не объявляется скринридером — это не стилистика, это неработающий
  интерфейс для части пользователей.
- Заголовки идут по порядку, без пропусков уровней. `h1` на странице один.
- У каждого поля формы есть связанный `label` (через `for` или обёрткой).
  Плейсхолдер не заменяет подпись: он исчезает при вводе.
- У изображений есть `alt`. Для декоративных — пустой `alt=""`, чтобы
  скринридер их пропустил, а не зачитывал имя файла.
- Интерактивный элемент доступен с клавиатуры и имеет видимый фокус.
  `outline: none` без замены — самая частая причина, по которой страницей
  нельзя пользоваться без мыши.
- `aria-*` добавляется, только когда нативного элемента не хватает. Неверный
  `aria` хуже отсутствующего: он переопределяет то, что браузер уже знал.
- У страницы задан `lang`, у `viewport` нет `user-scalable=no` — запрет
  масштабирования ломает доступность на телефоне.
- Скрипты не блокируют разбор документа: `defer` или `type="module"`.
- Изображениям заданы `width` и `height` (или `aspect-ratio`) — иначе контент
  прыгает при загрузке.
- Порядок элементов в разметке совпадает со зрительным порядком: перестановка
  через CSS ломает переход по табу.
