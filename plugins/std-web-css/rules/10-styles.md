# CSS: каскад и раскладка

Главная беда CSS не в синтаксисе, а в том, что каждое правило действует
глобально. Стиль, написанный для одной страницы, ломает другую через полгода,
и связь между причиной и следствием не видна.

- Специфичность держим низкой и плоской. `!important` — признак того, что
  селектор перебивает сам себя; убирается пересмотром селектора, а не ещё
  одним `!important`.
- Не привязываемся к структуре разметки: `.card > div:nth-child(2)` ломается
  от любой перестановки. Класс на элементе устойчив, вложенность — нет.
- Цвета, отступы, радиусы, тени — через переменные (`--token`). Хардкод
  `#3b82f6` в двадцати местах невозможно поменять разом и невозможно найти.
- Раскладка — grid и flexbox. Абсолютное позиционирование — только для того,
  что действительно выпадает из потока: подсказки, модалки, бейджи.
- Размеры в `rem` для типографики и отступов: пользователь, увеличивший
  шрифт в браузере, должен получить увеличенный интерфейс, а не сломанный.
- Фиксированная высота у блока с текстом — источник обрезанного контента
  при другом языке или размере шрифта. Ограничивай `min-height`.
- Адаптивность от меньшего к большему: базовые стили без медиазапроса,
  расширения — в `min-width`.
- Анимируем только `transform` и `opacity`. Анимация `width`, `top`, `height`
  заставляет браузер пересчитывать раскладку в каждом кадре.
- Уважаем `prefers-reduced-motion`: для части людей движение вызывает
  физическое недомогание.
- `z-index` — из заданной шкалы, а не произвольные числа. `z-index: 9999`
  всегда порождает `z-index: 10000` этажом выше.
- Скрываем визуально, но оставляем для скринридера — специальным классом,
  а не `display: none`: последнее убирает элемент и из доступности.
