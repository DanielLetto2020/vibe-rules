# SQLite

SQLite удобен для тестов и локальной разработки, и именно поэтому опасен:
он молча прощает то, на чём падает прод.

- **Тип значения после чтения различается между драйверами.** SQLite вернёт
  целочисленную колонку как число, Postgres может вернуть строку. Проверка
  `$x === 3`, зелёная на SQLite, ломается на проде. Сравнивай типобезопасно
  и не проверяй гипотезы про типы на движке, которого нет в проде.
- Гипотезы о поведении БД вообще не проверяются на SQLite, если в проде
  Postgres: отличаются типы, регистр строк, сортировка, конкурентность,
  оконные функции, блокировки.
- Внешние ключи по умолчанию **выключены**: `PRAGMA foreign_keys = ON`
  на каждое соединение. Иначе целостность не проверяется, и тесты пропускают
  ошибки, которые прод поймает.
- Для любой параллельной записи — `PRAGMA journal_mode = WAL`. Без него
  вторая запись получает `database is locked`.
- Динамическая типизация: в колонку `INTEGER` запишется строка. Ограничения
  и проверки, если они важны, задаются явно через `CHECK`.
- `ALTER TABLE` умеет мало: переименование и смена типа колонки делаются
  через создание новой таблицы, копирование и переименование.
- Один файл — один писатель. Если сервис масштабируется горизонтально,
  SQLite не подходит, и это архитектурное решение, а не деталь конфигурации.
