# Python-парсеры: работа с сетью

Парсер по определению работает с чужой нестабильной системой. Всё, что здесь
перечислено, — про поведение при отказах, а его тесты на happy path не ловят.

- У каждого запроса есть таймаут. Запрос без таймаута однажды повесит процесс
  навсегда — не «выдаст ошибку», а именно повиснет.
- Ретраи — с экспоненциальной задержкой и джиттером, с ограничением попыток.
  Повторяем только идемпотентное и только на 5xx/сетевых сбоях, не на 4xx.
- Соблюдаем rate limit источника, `Retry-After` уважаем.
- Разбор ответа устойчив к изменению разметки: отсутствующее поле даёт понятную
  ошибку с контекстом (url, селектор), а не `IndexError` в пятом кадре стека.
- Кодировку берём из ответа, не угадываем; результат нормализуем в UTF-8.
- Сырой ответ при ошибке разбора сохраняем — иначе баг невоспроизводим.
- Секреты и куки — из окружения. В репозиторий не попадают даже «временно».
