# HTTP API: доступ и защита

API отличается от интерфейса тем, что его вызывают программы, а значит —
быстро, много и не так, как задумано. Проверка, которую в интерфейсе делает
форма, здесь должна быть в коде.

- Проверка права выполняется на каждом методе и на каждый объект.
  Идентификатор в адресе — это ввод пользователя, а не подтверждение
  доступа к записи.
- Метод, доступный без аутентификации, помечен явно и таких методов
  пересчитанное число. Незакрытый по забывчивости выглядит так же, как
  открытый намеренно.
- Отсутствие доступа и отсутствие объекта различаются осознанно: ответ
  «не найдено» скрывает существование чужих записей, ответ «нет доступа»
  его подтверждает.
- Токены передаются в заголовке, а не в адресе: адреса попадают в журналы
  прокси, историю браузера и отчёты об ошибках.
- Срок жизни токена ограничен, отзыв возможен, обновление отделено
  от основного токена.
- Ограничение частоты применяется и к аутентифицированным вызовам,
  и к попыткам входа. Без второго перебор паролей ограничен только сетью.
- Размер тела запроса ограничен на уровне сервера, а не только приложения:
  разбор гигабайтного JSON начинается раньше, чем код успеет что-то
  проверить.
- Массовые операции ограничены по числу элементов: список на десять тысяч
  идентификаторов в одном запросе — это отказ в обслуживании без атаки.
- Ответ содержит только те поля, которые нужны вызывающему. Лишнее поле
  в ответе — это утечка, обнаруживаемая через год.
- Загрузка файлов проверяется по содержимому и размеру, а выдача файлов
  идёт через проверку прав, а не по угадываемой ссылке.
- Действия, меняющие данные и деньги, записываются в аудит: кто, что, когда,
  с какого адреса.
- Внешние вызовы по адресу из запроса запрещены или ограничены списком:
  иначе API превращается в средство обращения во внутреннюю сеть.
