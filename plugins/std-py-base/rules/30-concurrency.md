# Python: параллельность и асинхронность

В Python три разных механизма параллельности, и они решают разные задачи.
Выбор наугад даёт код, который либо не ускоряется вовсе, либо ломается
непредсказуемо под нагрузкой.

- Ожидание ввода-вывода — `asyncio` или потоки; вычисления — процессы.
  Потоки не ускоряют счёт: интерпретатор выполняет байт-код по одному.
- Блокирующий вызов внутри `async` останавливает всё событийное окно,
  а не только свою задачу. Синхронную библиотеку выносят в пул потоков.
- У каждой асинхронной операции есть таймаут и способ отмены. Задача,
  которую некому прервать, переживает и запрос, и смысл своего результата.
- Созданная задача сохраняется в переменную и ожидается или отменяется
  явно: ссылка на задачу, которую никто не держит, может быть собрана
  сборщиком мусора вместе с задачей.
- Отмена — это исключение. Блок очистки должен отработать, а `except`
  не должен глотать отмену наравне с ошибками.
- Общее изменяемое состояние между потоками защищено блокировкой или
  заменено очередью. Операция вида «прочитал, увеличил, записал» не атомарна
  даже для целого числа.
- Порядок захвата блокировок одинаков во всём коде — это единственный
  надёжный способ не получить взаимную блокировку.
- Число одновременных обращений к внешнему ресурсу ограничено семафором
  или пулом: тысяча задач, стартовавших разом, кладут базу, а не ускоряют.
- Пул процессов получает данные, которые сериализуются. Объекты с открытыми
  соединениями и файлами через границу процесса не проходят.
- Фоновая работа завершается при остановке приложения: обработчик сигнала,
  ожидание текущих задач, ограничение по времени. Убитый на полпути процесс
  оставляет незавершённые операции.
