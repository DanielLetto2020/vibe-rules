# Python: данные и структуры

Динамическая типизация означает, что структура данных существует только
в голове автора. Через полгода словарь с восемью ключами читается угадыванием,
а опечатка в имени ключа обнаруживается в проде.

- Структура данных описывается классом (`dataclass` или модель валидации),
  а не словарём со свободными ключами. Опечатка в имени поля тогда ошибка
  сборки, а не пустое значение.
- Словарь используется там, где ключи заранее неизвестны: настройки,
  разобранный ответ, счётчики. Как замена объекту — нет.
- Изменяемые значения не кладутся в аргументы по умолчанию и в атрибуты
  класса: они общие для всех вызовов и всех экземпляров.
- Копирование поверхностное по умолчанию: срез списка не копирует вложенные
  объекты. Для полной копии — явное глубокое копирование.
- Кортеж для неизменяемой записи фиксированной длины, список — для
  однородной последовательности. Смешение делает непонятным, что можно менять.
- Множество для проверки принадлежности: поиск в списке из тысяч элементов
  выполняется перебором.
- Генератор вместо списка там, где данные обрабатываются потоком: список
  на миллион элементов занимает память целиком.
- Сортировка со сравнением по ключу (`key=`), а не самодельным компаратором;
  для устойчивой сортировки по нескольким полям — кортеж ключей.
- Числа для денег — целые в минимальных единицах или десятичный тип.
  Дробное число даёт расхождение в копейках, которое находит бухгалтерия.
- Строки нормализуются на входе: пробелы, регистр, форма представления
  символов. Две визуально одинаковые строки могут быть разными.
- Сериализация в JSON описывается явно: типы даты, десятичного числа
  и множества стандартом не поддерживаются, и «оно как-то работало» означает
  неявное преобразование.
- Перечисления (`Enum`) вместо строковых констант: опечатка в строке
  не ловится ничем.
