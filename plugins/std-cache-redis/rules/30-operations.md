# Redis: эксплуатация

Redis держит данные в памяти, и это определяет всё остальное: что происходит
при её исчерпании, что переживёт перезапуск и во что обойдётся одна медленная
команда.

- Предел памяти задан, и задана политика при его достижении. Без предела
  сервер растёт, пока система не убьёт процесс, — то есть внезапно
  и целиком.
- Сохранение на диск настроено под роль: для кэша его можно отключить,
  для очередей и сессий — нельзя. Решение принимается явно, а не остаётся
  умолчанием.
- Приложение переживает недоступность Redis: короткий таймаут, работа
  из источника, понятная деградация. Кэш, отказ которого роняет сайт, —
  это не кэш, а хранилище.
- Медленные команды отслеживаются. Одна операция над большим значением
  блокирует весь сервер — он однопоточный, и очередь ждёт.
- Ключи, растущие без предела (списки, множества, потоки), имеют механизм
  обрезки. Структура без ограничения однажды займёт всю память одна.
- Распределение памяти по типам данных отслеживается: рост обычно даёт одна
  группа ключей, и найти её без разбивки нельзя.
- Подключение идёт через пул с ограничением: тысяча соединений от каждого
  экземпляра приложения исчерпывает лимит быстрее, чем память.
- Разные назначения — разные экземпляры или базы: очистка кэша не должна
  задевать сессии и очереди.
- Доступ закрыт паролем и сетевыми правилами. Redis без пароля, доступный
  из сети, обнаруживают сканеры за часы.
- Обновление версии и переключение узлов проверяются заранее: клиентские
  библиотеки по-разному ведут себя при смене ведущего узла.
- Восстановление после потери данных описано: что прогреется само, что
  придётся пересчитать, что потеряно навсегда. Ответ нужен до аварии,
  а не во время.
