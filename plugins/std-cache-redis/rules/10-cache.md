# Redis

Кэш — это ускорение, а не хранилище. Система обязана оставаться корректной,
если Redis очистится целиком: перезапуск, вытеснение по памяти, переключение
на реплику.

- У каждого ключа есть TTL. Ключ без срока жизни живёт вечно и однажды
  съедает память — обычно в самый неподходящий момент.
- Ключи именуются по схеме `сущность:идентификатор:версия`. Версия в имени
  делает инвалидацию при смене формата тривиальной.
- Промах кэша — нормальный путь, а не ошибка: данные берутся из источника.
- Инвалидация происходит там же, где изменение данных, в той же операции.
  Отложенная инвалидация «потом, в фоне» означает, что пользователь увидит
  устаревшие данные и не поймёт почему.
- Не кэшируем то, что зависит от прав доступа, без включения субъекта в ключ.
  Иначе один пользователь увидит данные другого — самая дорогая ошибка кэша.
- Блокировки (`SET NX` с TTL) обязаны иметь срок и владельца: снимать чужую
  блокировку нельзя, а блокировка без TTL при падении процесса вешает систему
  навсегда.
- `KEYS` в продовом коде запрещён — он блокирует сервер целиком. Перебор —
  только `SCAN`.
- Недоступность Redis не роняет запрос: таймаут короткий, ошибка приводит
  к чтению из источника, а не к 500.
- Redis в роли очереди без подтверждений теряет задачи при падении
  потребителя. Если потеря недопустима — нужен брокер, а не список.

## Где кэшировать

Выбор между локальным и общим кэшем определяется не удобством,
а требованием к согласованности:

- **Локально в экземпляре приложения** (файл, память процесса) — когда данные
  вычисляются один раз и остаются верными всю его жизнь: карта маршрутов,
  собранный контейнер зависимостей, скомпилированные шаблоны. Общий кэш здесь
  добавляет сетевой вызов без выгоды.
- **В общем хранилище** — когда состояние обязано обновиться сразу во всех
  экземплярах: сессии, профиль пользователя, признаки доступа. Локальный кэш
  здесь даёт разные ответы от разных экземпляров, и воспроизвести это
  невозможно.
